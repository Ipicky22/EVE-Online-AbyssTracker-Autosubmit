# EVE Online AbyssTracker Autosubmit

[English](README.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | **Русский** | [中文](README.zh.md)

> Этот перевод не проверен носителем русского языка. Основной считается [английская версия](README.md).

Автоматически отправляет ваши прохождения Бездны (Abyssal Deadspace) в EVE Online на [Abyss Tracker](https://abysstracker.com).
Программа называется `abysstracker-autosubmit`.
Она никогда не вмешивается в клиент EVE: читает только журнал локального чата, который EVE записывает на диск, и буфер обмена Windows.

> **Статус: в разработке.** Отправка работает. Чтение буфера обмена Windows ещё не испытано на настоящем компьютере, см. [Состояние проверок](#состояние-проверок).

## Использование

1. Запустите `abysstracker-autosubmit.exe`: откроется страница `http://localhost:47813`.
2. Выберите погоду, уровень, класс корабля и фит, затем нажмите **Начать сессию**.
3. Скопируйте грузовой отсек (`Ctrl+A`, `Ctrl+C`) перед первым прохождением.
4. После каждого прохождения снова скопируйте грузовой отсек: прохождение отправится на Abyss Tracker.
5. После смены системы или стыковки снова скопируйте грузовой отсек перед следующим прохождением.

Прохождения публикуются открыто.
Прохождение без надёжной копии грузового отсека не отправляется: оно сохраняется в `incomplete/`.

На странице показан список прохождений, отправленных за сессию, с длительностью и стоимостью добычи, рассчитанными Abyss Tracker.
Список обновляется сам и не сохраняется, когда начинается новая сессия.

## Настройка (один раз)

1. Создайте токен на `abysstracker.com/my-account/personal-access-tokens`.
2. На странице откройте **Настройки**, вставьте токен и сохраните.

Не нужны ни приложение разработчика EVE, ни вход персонажем.
EVE должна записывать чат в файл (так по умолчанию).
Если ваши журналы лежат не в `Documents\EVE\logs\Chatlogs`, укажите папку в **Настройках**.

## Языки

| | Английский | Французский | Немецкий | Русский | Китайский |
|---|---|---|---|---|---|
| Интерфейс (**Настройки → Язык**) | да | да | да | да | да |
| Клиент EVE: названия предметов | да | да | да | да | да |
| Клиент EVE: журнал локального чата | предположительно | проверено | предположительно | предположительно | предположительно |

«Проверено» значит испытано на настоящем файле журнала. «Предположительно» значит, что формулировки взяты из
открытых программ, читающих журналы EVE, и не испытаны на настоящем журнале этого языка: обнаружение
прохождений может не работать.
Файл локального журнала на одном из этих языков будет кстати, см. [Известные ограничения](#известные-ограничения).
Немецкие, русские и китайские тексты не проверены носителями языка.
Названия предметов всегда отправляются на Abyss Tracker на английском.

## Параметры

- `-dry-run`: записывает прохождения в журнал программы вместо отправки.
- `-no-open`: не открывает браузер при запуске.

## Данные

В `%APPDATA%\abysstracker-autosubmit\` (`~/.config/abysstracker-autosubmit/` в Linux):
`config.json`, `names.json` (кэш названий предметов), `abysstracker-autosubmit.log`
и папки `pending/`, `sent/`, `incomplete/`, `rejected/`.

Токен хранится открытым текстом в вашем профиле пользователя и никогда не попадает в этот репозиторий.

При запуске и затем каждые 6 часов программа запрашивает у GitHub последний релиз этого репозитория, чтобы сообщить на странице о выходе новой версии.
Запрос не содержит ни токена, ни данных персонажа.

## Как это работает

- **Персонаж**: читается из самого нового файла `Local_<дата>_<время>_<ID персонажа>.txt`.
- **Начало, конец и длительность прохождения**: при каждой смене системы EVE пишет строку в журнал локального чата. При входе в Бездну система показана как `Unknown` (`Inconnu` во французском клиенте). Точность до секунды, без сетевых запросов.
- **Гибель**: выход из Бездны в другую систему, а не в ту, где использована нить (пробуждение в клоне).
- **Добыча**: разница между копией грузового отсека до прохождения и после него. Названия предметов переводятся в идентификаторы типов через открытый API EVE (ESI), с кэшем на диске.
- **Погода, уровень, класс корабля, фит**: берутся из настроек сессии.

## Известные ограничения

- Журнал не сообщает о стыковке. Смена системы сбрасывает известный груз и требует новой копии, но если вы пристыкуетесь, **не покидая систему**, и забудете скопировать груз заново, добыча следующего прохождения будет неверной.
- Гибель не определяется, если ваш клон находится в системе, где использована нить.
- Только один персонаж одновременно.
- Слово, которым в локальном журнале обозначена Бездна (`Unknown`, `Unbekannt`, `Неизвестно`, `未知`), проверено только для французского (`Inconnu`). Если для вашего языка оно неверно, прохождения просто не обнаруживаются и ничего не отправляется.

## Разработка

```
go test ./...
GOOS=windows go build -ldflags "-H=windowsgui" -o abysstracker-autosubmit.exe .
```

Перед релизом укажите в `version` (файл `update.go`) тег релиза.

## Состояние проверок

Проверено:

- обнаружение прохождения по настоящему французскому журналу локального чата: персонаж, вход, выход, длительность до секунды;
- токен Abyss Tracker принимается в заголовке `X-API-KEY`;
- `fits/list` возвращает фиты аккаунта вместе с кораблём;
- тестовое прохождение, отправленное кодом отправки самой программы, появляется на Abyss Tracker с верными погодой, уровнем, классом корабля, фитом, длительностью и добычей;
- израсходованные нити, отправленные в списке потерянных предметов, учитываются один раз.

Осталось подтвердить:

- Abyss Tracker относит отправленные прохождения только к двум типам добычи: «all cans» или «Bioadaptive and some cans». Флажок в сессии выбирает, к какому. То, что первый получается при равных числах контейнеров, предположение: на отправке это ещё не наблюдалось;
- чтение буфера обмена Windows и уведомления: скомпилированы, ни разу не запускались на настоящей Windows.
